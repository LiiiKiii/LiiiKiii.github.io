## 客观评价测试方案（evaluation_objective）

本目录用于设计和记录 **客观评价实验**，包括：

- **与 NotebookLM 的直接对比实验（客观指标）**
- **“笨学生”方法下，本系统前后效果对比实验**
- **与性能脚本的衔接（运行时性能与资源占用）**

所有指标都尽量做到 **可复现、可量化**，用于论文/报告中的表格和图表。

---

### 1. 与 NotebookLM 的直接对比（客观）

#### 1.1 控制变量与测试流程

- **控制变量**：
  - 输入材料文本完全一致；
  - 任务指令(prompt) 使用统一模板，只替换材料内容与问题文本；
  - 对于可控参数（温度、max tokens 等），在两个系统中尽量对齐或说明差异。

- **测试流程（单个任务，用于客观指标）**：
  1. 将同一材料导入 NotebookLM 和本系统；
  2. 使用完全相同的任务指令发起请求；
  3. 记录：
     - \(T_{\text{first\_token}}\)：从请求发出到第一个 token 出现的时间；
     - \(T_{\text{full}}\)：到完整回答加载完成的时间；
     - 运行时资源占用（CPU 利用率峰值与平均值、内存占用峰值等）。
  4. 输出文本本身用于主观评分（见 `evaluation_subjective`），这里不重复描述主观评价细节。

#### 1.2 性能与“耗能”近似指标

- **响应时间（Latency）**：
  - \(T_{\text{first\_token}}\)：反映交互延迟感；
  - \(T_{\text{full}}\)：反映整体完成时间。
- **资源占用（近似耗能）**：
  - 使用系统监控工具（如 Activity Monitor、`top`、`psutil` 等）记录：
    - CPU 利用率峰值与平均值；
    - 内存占用峰值。
  - 在论文中可以将这些作为“相对耗能指标”，强调是近似测量。

> 实际使用时，可按任务、材料类型拆分多个表格，并与主观评分结果进行对照分析。

### 2. “笨学生”方法（系统前后对比）

#### 2.1 “笨学生”设定

通过统一的系统 prompt 将同一 LLM 人为限制为“笨学生”，仅保留最低限度能力。示例约束：

- 不允许主动生成大纲、总结、知识结构；
- 不做多步推理，只做一次性简单回答；
- 不使用比喻、类比等教学技巧；
- 只允许从给定文本中“查找并摘抄相关句子，做最少量的重述”；
- 如果有工具调用：禁止调用高级检索或知识库，只保留简单全文搜索。

> 可以在本目录新增 `dumb_student_prompt.md`，写出实际使用的限制 prompt，保证复现性。

#### 2.2 系统增强设定

在“系统增强”条件下，允许本系统调用完整 pipeline 与全部能力，例如：

- 自动构建知识结构、大纲、学习路径；
- 主动拆分步骤、解释中间推理过程；
- 根据学习者水平调整解释难度（如有此功能）；
- 合理调用内部检索/知识库等组件。

#### 2.3 任务与实验流程

- **任务集设计**：
  - 选择一组覆盖不同难度的任务：
    - 概念理解题：解释关键概念、比较相近概念；
    - 推理/证明题：需要多步逻辑推理的题目；
    - 综合应用题：把多条知识综合应用到新情境。

- **实验流程（单个任务）**：
  1. 使用 **相同材料 + 相同用户问题**，在“笨学生 prompt”下生成回答（记为 `Answer_dumb`）；
  2. 使用 **相同材料 + 相同用户问题**，在“系统增强条件”下生成回答（记为 `Answer_sys`）；
  3. 对两份回答进行匿名化处理，随机打乱顺序，交给评审打分。

#### 2.4 评价指标

- **专家打分**：
  - 与 1.3 部分相同维度：正确性、完整性、结构化程度、可教性；
  - 记录每个维度的前后差异。

- **提升量化**：
  - 计算每道题的分数差：
    - \(\Delta = \text{Score}_{\text{sys}} - \text{Score}_{\text{dumb}}\)
  - 统计：
    - 平均提升 \(\overline{\Delta}\)；
    - 提升显著的案例；
    - 系统表现持平或变差的异常案例（用于分析）。

### 3. 与性能脚本的关系（可选）

`../performance/run_performance_tests.py` 可用于：

- 单独评估本系统内部模块（如推荐、关键词提取）的 **纯性能指标**（latency、tokens/s 等）；
- 这些结果可作为客观评价的补充，在论文中说明“本系统在资源约束下的效率表现”。

如果你希望直接在脚本中集成“NotebookLM 对比”或“笨学生 vs 系统”实验逻辑，可以：

- 在脚本中增加新的测试函数（例如 `test_vs_notebooklm()`）；
- 使用统一的数据集配置文件，从本目录读取任务与材料；
- 将输出结果写入 CSV/JSON，再用本 README 中的表格模板进行整理。
