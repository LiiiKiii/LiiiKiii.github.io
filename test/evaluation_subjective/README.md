## 主观评价测试方案（evaluation_subjective）

本目录用于设计和收集 **主观评价数据**，重点从“学习者视角”比较：

- 使用本系统与使用 NotebookLM 时的主观体验差异；
- 在“笨学生输出”和“系统增强输出”之间，学习者对“哪一份更好学、更有帮助”的感受。

主观评价主要通过问卷、打分和开放式反馈实现。

---

### 1. 与 NotebookLM 的直接对比（主观）

#### 1.1 控制变量与测试流程

- **控制变量**：
  - 输入材料文本完全一致；
  - 任务指令(prompt) 使用统一模板，只替换材料内容与问题文本；
  - 对于可控参数（温度、max tokens 等），在两个系统中尽量对齐或说明差异。

- **测试流程（单个任务，用于主观打分）**：
  1. 将同一材料导入 NotebookLM 和本系统；
  2. 使用完全相同的任务指令发起请求；
  3. 记录两套 **输出文本**（原始回答），供后续主观评分和偏好选择使用；
  4. 具体的响应时间和资源占用由 `evaluation_objective` 中的客观实验负责记录。

#### 1.2 文本质量主观评价指标

- **输出质量（LLM 增强效果，主观评分）**：
  - 邀请 2–3 名有相关背景的评审，按统一 rubric 对回答打分：
    - 正确性（0–5）：是否有事实性错误、理解偏差；
    - 完整性（0–5）：是否覆盖关键点，有无重大遗漏；
    - 结构化程度（0–5）：是否有清晰的层级结构、过渡自然；
    - 可教性/易学性（0–5）：像不像在给学生“讲明白”，而不只是给结论。
  - 若任务有标准答案或参考解：
    - 记录 **正确 / 部分正确 / 错误**，计算正确率或平均得分（基于评审主观判断）。
  - 进行 **A/B 盲测偏好**：
    - 将 NotebookLM 和本系统的输出打乱呈现为 A/B，不标注来源；
    - 让评审选择更喜欢的回答，并记录偏好比例。

> 注意：**响应时间 / 资源占用等“硬指标”只在 `evaluation_objective` 中记录和分析，这里只保留“文本质量”和“主观偏好”相关内容。**

### 1. 评价维度与核心问题

建议主观问卷围绕以下几个维度（每题使用 5 或 7 点李克特量表）：

- **感知学习效果**：
  - 例：”使用该系统后，我更容易理解学习材料中的概念。“
  - 例：”与只读原文相比，该系统明显提升了我解题/应用知识的能力。“

- **易用性与流程体验**：
  - 例：”系统界面易于理解，上手成本较低。“
  - 例：”完成一个学习任务的操作流程清晰，不需要反复摸索。“

- **信任度与安全感**：
  - 例：”我相信系统给出的解释和推理过程。“
  - 例：”在重要任务（如作业、考试复习）中，我愿意依赖系统提供的答案或检查结果。“

- **透明度与可控性**：
  - 例：”我能理解系统在背后做了哪些步骤（如检索、整合、总结）。“
  - 例：”当我不满意当前回答时，我知道如何引导系统调整输出。“

- **整体满意度与偏好**：
  - 例：”总体来说，我对该系统的使用体验感到满意。“
  - 例：”在日常学习中，我更倾向于使用该系统而不是 NotebookLM 完成类似任务。“

> 建议在本目录新建 `questionnaire.md`，列出完整问卷题目与选项。

### 2. NotebookLM vs 本系统的主观对比

#### 2.1 体验流程设计

为降低顺序效应，建议采用交叉设计（可视实际情况简化）：

- 将受试者随机分为两组：
  - **A 组**：先使用 NotebookLM 完成一组任务，再使用本系统完成另一组难度相当的任务；
  - **B 组**：顺序相反。
- 确保两组任务在 **材料类型与难度上尽量匹配**。

每位受试者在完成两种系统体验后，填写同一份问卷，但问卷中单独设置对比题目，例如：

- “在**理解复杂概念**时，你更愿意使用哪个系统？”（单选：NotebookLM / 本系统 / 无明显差别）
- “在**整理学习大纲/知识结构**时，你更愿意使用哪个系统？”
- “在**考前复习与自测**时，你更愿意使用哪个系统？”

#### 2.2 UI 对照展示（用于问卷前/中说明）

可以在本目录下准备 `ui_notebooklm.png` / `ui_our_system.png` 等示意图，用于：

- 展示两种系统在同一任务下的典型界面与输出；
- 强调本系统的直观优势（如知识结构、学习路径、错题反馈等）。

这部分不直接量化，但有助于受试者理解差异，也可在访谈中使用。

### 3. “笨学生” vs “系统增强”的主观评价

在客观评价中，我们已有“笨学生版输出”和“系统增强版输出”。主观部分关注：

- 学习者更愿意阅读/学习哪一份；
- 哪一份更“像老师在教我”，而不是仅给结论。

#### 3.1 题目设计（示例）

对于每一道题，向受试者呈现两份匿名回答（顺序随机），并提问：

- “你更愿意阅读哪一份回答来帮助自己理解该知识点？”（单选：回答 A / 回答 B）
- “哪一份回答更像在‘教你’而不是只给出答案？”（单选）
- “哪一份回答更有助于你 **举一反三** 地解决类似问题？”（单选）

同时，可以加入 1–2 个简单打分题：

- “你觉得自己从这两份回答中学到了多少？”（1–5 分）
- “你对回答的信任程度如何？”（1–5 分）

> 这些题的统计结果可以与客观评分中的提升量 \(\Delta\) 做对照分析。

### 5. 主观 vs 客观的对应关系（建议）

为方便论文撰写，可在这里明确主观问题与客观指标的映射，例如：

- 主观“学习效果” ↔ 客观任务得分、正确率；
- 主观“易用性/流程顺畅度” ↔ 实际完成同类任务所需步骤数 / 时间；
- 主观“信任度” ↔ 客观错误率、严重误导性回答的比例；
- 主观“更适合整理大纲/知识结构” ↔ 客观结构化程度得分。

这样可以在结果讨论部分更自然地把主观和客观结果联系起来。

### 6. 需要准备的内容

- 问卷题目完整列表（`questionnaire.md`）；
- UI 截图或 demo 链接（NotebookLM 与本系统，并排展示）；
- 问卷发放渠道（如在线表单链接）；
- 回收后的原始数据（CSV/Excel）与清洗后的分析表；
- 与 `evaluation_objective` 中任务/题目 ID 的对应关系说明。

主观评价部分与客观评价配合使用，目标是在论文中同时回答两个问题：

1. **系统是否在客观上更强？**
2. **系统是否在主观体验上更“好用、更好学、更值得信任”？**
